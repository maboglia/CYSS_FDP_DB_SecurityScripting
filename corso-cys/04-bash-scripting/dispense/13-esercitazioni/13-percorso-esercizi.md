# 13 – Esercitazioni progressive di Bash

<text>Durata indicativa: 60 minuti per ogni laboratorio · Livello: progressivo</text>

## Metodo di lavoro
Ogni esercizio va svolto seguendo il ciclo: comprendere la richiesta, individuare input
e output, progettare i passaggi, scrivere lo script, provarlo con casi normali e casi
limite, correggere e documentare. Le attività si svolgono in una directory dedicata.

## Laboratorio A – Fondamentali (circa 60 minuti)
1. Stampare un messaggio personalizzato.
2. Creare una directory di laboratorio e mostrare il percorso.
3. Creare un file con tre righe e visualizzarne le prime due.
4. Mostrare i permessi di uno script e renderlo eseguibile.
5. Scrivere una breve nota con i comandi utilizzati.

Codice di riferimento: `01-primo-script.sh`, `02-comandi-laboratorio.sh`.

## Laboratorio B – Input e controllo (circa 60 minuti)
1. Leggere un nome e salutare l'utente.
2. Acquisire un numero e verificare che sia un intero.
3. Stabilire se è pari o dispari.
4. Stampare un messaggio diverso in base alla scelta di un menu.

Codice di riferimento: `04-input-read.sh`, `06-pari-dispari.sh`, `07-menu-case.sh`.

## Laboratorio C – Cicli e funzioni (circa 60 minuti)
1. Stampare una sequenza da 1 a 20.
2. Leggere un file riga per riga.
3. Creare una funzione che riceva un nome.
4. Sommare due numeri passati come argomenti.
5. Gestire argomenti mancanti e input non valido.

Codice di riferimento: `08-stampa-numeri.sh`, `09-leggi-file.sh`,
`10-funzione-saluto.sh`, `11-somma-argomenti.sh`.

## Laboratorio D – File e automazione (circa 60 minuti)
1. Cercare una parola in un file.
2. Selezionare righe che iniziano con una maiuscola.
3. Preparare un backup datato.
4. Simulare la rinomina con anteprima.
5. Verificare i permessi di file di prova.

Codice di riferimento: `12-cerca-testo.sh`, `13-righe-maiuscole.sh`,
`18-backup-txt.sh`, `19-rinomina-jpg-preview.sh`, `15-verifica-permessi.sh`.

## Laboratorio E – Cybersecurity (circa 60 minuti)
1. Cercare gli eventi `ERROR` in un log didattico.
2. Contare i livelli `INFO`, `WARNING`, `ERROR`.
3. Controllare i permessi di una directory di prova.
4. Produrre un breve report e descrivere i limiti dell'analisi.

Codice di riferimento: `20-conta-eventi-log.sh`, `21-controllo-file-sensibili-demo.sh`.

## Criteri di valutazione
- correttezza funzionale;
- chiarezza e commenti essenziali;
- uso appropriato di quoting e controlli;
- gestione degli errori e degli input non validi;
- rispetto delle cautele operative;
- capacità di spiegare il comportamento del programma.

## Consegna
Per ogni laboratorio consegnare script, input di prova, output osservato e una breve
spiegazione delle scelte. Non includere dati personali o log reali non autorizzati.
